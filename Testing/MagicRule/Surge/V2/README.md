# V2：逐条域名分类补充草稿

本版目标是补漏和优化，不把现有配置视为正确答案。仅沿用用户策略组，以及明确指定的 Landing 例外。与旧版隔离，未接入任何主配置。

## 如何分配
- 逐条比对独立上游 v2fly 的国内/国外及服务分类、Firefly 的原始分类；保留分类依据。
- 先区分具体域名的服务及地区；不再用整个文件的名称或70%覆盖比例决定去向。
- 国内AI/普通国内服务归 DIRECT；国外AI归AI；国外GitHub/流媒体/游戏等归相应策略，普通国外服务归Select。
- 共享云、IP/ASN、进程、正则等不凭可达性和品牌强行分类，完整保留 Pending。
- Cleanup 依据明确广告/隐私列表中的实际条目，不能保证上游没有误伤，需独立测试。

## 文件
- Rules/：按策略及地区整理的域名文件，适合审阅；直接按文件组串接会遇到父子覆盖，请勿随意整套启用。
- Ordered/及rules-example.conf：按域名深度和精确匹配分层，避免不同策略的具体子域被父域抢先。仅为待验证引用方案，不是主配置。
- assignment.csv.gz：全部原始唯一规则的逐条归属、来源、依据和待核对原因。
- Pending/all-unassigned.list：未确认规则，原始类型与参数保留。
- report.json及checks.json：计数、完整性及代表域名离线检查。

## 边界
分类是来源支持的候选分流，不等同于可达性、解锁或Surge核心实测。原库/上游自身存在混杂和重叠，未全部人工判定；Cleanup较大且部分规则需复核。无独立归属依据的规则没有强行归直连或代理，也没有静默丢弃。正式配置不受影响。
